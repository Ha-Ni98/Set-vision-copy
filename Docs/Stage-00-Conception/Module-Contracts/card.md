# Module Specification: Card

## 1. Context [CONTRACT]
- Prisma Entity: `Card`
- Depends on: SubscriptionPlan / Set / Lot / Distributor (resolved labels + names, distributor counter); Order (backend — for deriving the distribution timeline); `common` (`ApiResponse`, `ErrorCode`, `paginated`); Log (backend — inline audit)
- Scope note: a card's `cardStat` is **also** written by the Set, Order, and Activation modules inside their own transactions (generation, delivery cascade, activation lifecycle). This module owns only the **admin card actions** (delete / disable / enable / revoke) and the **reads**. The Cards page stat cards come from the **Statistics** module; "View Activation History" navigates to the Activation list filtered by `key`.

## 2. API Interface [CONTRACT]
`CARD_ROUTES` (`BASE: '/cards'`). All routes Admin-only.

- Route Constant: `CARD_ROUTES.GET_ALL` (GET `/cards`)
  - Access: Admin
  - Input (query/params): `GetCardsQuery` { page?, limit?, search?, state?, setNumber?, lotNumber?, distributorId?, subscriptionPlanId?, flag? } — `flag ∈ { disabled, revoked }`
  - Output: `CardDTO[]` (paginated)

- Route Constant: `CARD_ROUTES.GET_AVAILABLE_FOR_LOT` (GET `/cards/available-for-lot`)
  - Access: Admin
  - Input (query/params): `GetAvailableCardsQuery` { subscriptionPlanId }
  - Output: `AvailableCardDTO[]` (PRINTED, unassigned, not disabled — feeds Lot creation)

- Route Constant: `CARD_ROUTES.GET_BY_ID` (GET `/cards/:id`)
  - Access: Admin
  - Input (query/params): `CardIdParams` { id }
  - Output: `CardDetailDTO`

- Route Constant: `CARD_ROUTES.DELETE` (DELETE `/cards/:id`)
  - Access: Admin
  - Input (query/params): `CardIdParams`
  - Output: none

- Route Constant: `CARD_ROUTES.DISABLE` (POST `/cards/:id/disable`)
  - Access: Admin
  - Input (query/params): `CardIdParams`
  - Output: `CardDTO`

- Route Constant: `CARD_ROUTES.ENABLE` (POST `/cards/:id/enable`)
  - Access: Admin
  - Input (query/params): `CardIdParams`
  - Output: `CardDTO`

- Route Constant: `CARD_ROUTES.REVOKE` (POST `/cards/:id/revoke`)
  - Access: Admin
  - Input (query/params): `CardIdParams`
  - Output: `CardDTO`

DTOs:
- `CardDTO` = { id, key, subscriptionPlanId, subscriptionLabel, setNumber, lotNumber (nullable), distributorName (nullable), cardStat, isActive, isDisabled, isRevoked, createdAt }.
- `CardDetailDTO` = `CardDTO` + { distributionTimeline: { stat, at }[] }.
- `AvailableCardDTO` = { id, key, subscriptionLabel }.

## 3. Events [CONTRACT]
(none — audit logging is inline; the client-facing real-time lives in the Activation module)

## 4. Business Logic (Service) [BACKEND]
- **getAll:** require admin → query `Card` join plan/set/lot/distributor → filters (`search` by `key`; `state` multi-select; `setNumber`, `lotNumber`, `distributorId`, `subscriptionPlanId`; `flag`) → exclude soft-deleted (`deletedAt`) → paginate → resolve labels/names → map.
- **getAvailableForLot:** cards where `cardStat=PRINTED`, `subscriptionPlanId=param`, `lotId` null, `isDisabled=false` → map.
- **getById:** load or `RESOURCE_NOT_FOUND` → build `distributionTimeline` from set/lot/order timestamps → `CardDetailDTO`.
- **delete:** load → guard `cardStat ∈ {IN_SET, PRINTED}` (else `RESOURCE_CONFLICT`) → **soft-delete** (set `deletedAt`; `key` retained) → write `Log` `REMOVE_CARD`. (Set-level cascade hard-deletes cards because the parent `Set` row is removed; individual delete here is soft.)
- **disable:** load → guard `cardStat ∈ {IN_LOT, AT_DISTRIBUTOR}` and not already disabled (else `RESOURCE_CONFLICT`) → set `isDisabled=true`, `isActive=false`; if it was `AT_DISTRIBUTOR`, decrement `distributor.nbOfActiveCards` → return. (No log type.)
- **enable:** load → guard `isDisabled=true` (else `RESOURCE_CONFLICT`) → set `isDisabled=false`, `isActive=true`, `cardStat=AT_DISTRIBUTOR`; bump `distributor.nbOfActiveCards` → return. (No log type. Edge: a card disabled while `IN_LOT` lands on `AT_DISTRIBUTOR` on enable, per the conception's literal rule.)
- **revoke:** load → guard `cardStat=ACTIVATION_FAILED` and `isDisabled=false` (else `RESOURCE_CONFLICT`) → set `isRevoked=true`, `isActive=true`, `cardStat=AT_DISTRIBUTOR`; bump `distributor.nbOfActiveCards` → write `Log` `REVOKE_CARD` → return. (No undo on the `isRevoked` flag; the card can still be disabled afterward.)

## 5. Data Mapping [BACKEND]
- **toDTO:** resolve `subscriptionLabel`, `setNumber`, `lotNumber`, `distributorName`; pass the three flags and `cardStat`; `createdAt` → ISO. `distributionTimeline` is **derived** (IN_SET ← set.createdAt, PRINTED ← set.printedAt, IN_LOT ← lot.createdAt, IN_DELIVERY ← the lot's order.createdAt, AT_DISTRIBUTOR ← order.completedAt) — each entry present only when its source timestamp exists. The card carries no sensitive fields (account data lives in the Activation module).
- **toPersistence:** these actions flip state/flags only; `key` is generated by the Set module.

## 6. Technical Constraints [BACKEND]
- `key` unique (Set-generated). All actions are state-guarded per the table above. Individual delete is **soft** (`deletedAt`); set-cascade delete is hard. Disable/enable maintain `isActive` and the distributor's `nbOfActiveCards`; revoke returns the card to `AT_DISTRIBUTOR` with no flag-undo. Only `REMOVE_CARD` and `REVOKE_CARD` are logged. The distribution timeline is derived (no card-history table). All dates ISO 8601.

## 7. Test Scenarios [BACKEND]
- 200 — list with each filter; `flag=disabled`/`revoked` narrows correctly; 403 non-admin.
- 200 — `available-for-lot` returns only PRINTED, unassigned, non-disabled cards for the plan.
- 200 — detail includes the derived timeline (only the reached stages); 404 unknown id.
- 200 — delete an `IN_SET`/`PRINTED` card soft-deletes + logs `REMOVE_CARD`; 409 deleting an `IN_LOT`/`AT_DISTRIBUTOR`/active card.
- 200 — disable an `IN_LOT`/`AT_DISTRIBUTOR` card sets flags + decrements stock; 409 disabling in any other state or when already disabled.
- 200 — enable a disabled card → `AT_DISTRIBUTOR` + active + stock bump; 409 enabling a non-disabled card.
- 200 — revoke an `ACTIVATION_FAILED`, non-disabled card → `AT_DISTRIBUTOR` + `isRevoked` + logs `REVOKE_CARD`; 409 revoking a non-failed or disabled card.
